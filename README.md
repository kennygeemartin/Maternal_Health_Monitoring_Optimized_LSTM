# Maternal Health Risk Classification — Reproduction Package

This package reproduces the experiments reported in the manuscript
*An optimised long short-term memory network for maternal health risk
classification in a mobile decision-support prototype* (submitted to the
Journal of the Nigerian Society of Physical Sciences).

## 1. Contents

```
maternal_risk_reproduction/
├── data/
│   ├── Mathernal_Risk.csv                    # primary dataset (Mendeley)
│   ├── uci/Maternal Health Risk Data Set.csv # secondary dataset (UCI)
│   └── processed/                            # generated by prepare_data.py
├── src/
│   ├── prepare_data.py                       # cleaning + stratified split
│   ├── train_models.py                       # baselines + proposed LSTM
│   ├── train_uci.py                          # secondary (UCI) benchmark
│   └── make_figures.py                       # manuscript figures
├── results/                                  # metrics, histories, predictions
├── figures/                                  # manuscript figures (300 dpi)
├── models/                                   # weights, scaler, model card
├── requirements.txt
└── README.md
```

## 3. Environment

Python 3.10+ (developed with Python 3.12). Install dependencies:

```bash
pip install -r requirements.txt
```

Experiments were run on CPU (PyTorch 2.x, no GPU required).

## 4. Reproduction steps

Run the scripts in order from the package root:

```bash
python src/prepare_data.py     # cleaning + 70:15:15 split (seed 42)
python src/train_models.py     # LR, kNN, SVM, ANN baselines + proposed LSTM
python src/train_uci.py        # exploratory secondary (UCI) benchmark
python src/make_figures.py     # regenerate all manuscript figures
```

`prepare_data.py` writes `data/processed/cleaning_report.json` documenting the
exact row counts removed by each cleaning rule and the split sizes.
`train_models.py` writes `results/results.json` (all metrics, per-class tables,
confusion matrices, 95 % bootstrap accuracy intervals) and
`models/lstm_proposed.pt` + `models/standard_scaler.joblib` +
`models/model_card.json` for the selected model.

## 5. Model summary

* **Baselines** — logistic regression (multinomial), k-nearest neighbours
  (k = 15, distance-weighted), support vector machine (RBF kernel), and a
  feed-forward artificial neural network, all fitted on the same
  standardised training partition.
* **Proposed LSTM** — configuration selected from a documented four-candidate
  grid by validation macro-F1 (`results/grid_log.json`): standardisation,
  single bidirectional LSTM layer with 128 hidden units, dropout 0.3,
  label smoothing 0.05, batch 256, Adam (lr 10⁻³, weight decay 10⁻⁴),
  inverse-frequency class weights, cosine learning-rate decay, early stopping
  (patience 25, max 150 epochs). The selected configuration is recorded in
  `results/results.json → "Proposed LSTM" → "selected_config"` and
  `models/model_card.json`.

All eight static features are serialised as eight one-dimensional steps in the
fixed order declared in `models/model_card.json`. This is a feature-order
representation, **not** a temporal model of within-woman changes.

## 6. Scope and limitations

* Labels are general low/mid/high dataset risk categories, not clinical
  diagnoses.
* Records are static; no within-woman longitudinal structure exists in the
  public data, so no temporal-prediction claim is made.
* The split is record-level (no participant identifiers); repeated-person
  leakage cannot be excluded.
* The UCI experiment is a separately fitted benchmark with a different feature
  schema, not external validation of the primary model.

## 7. Prototype interface screenshots

`figures/fig7_measurement_entry.png`, `figures/fig8_stage_guidance.png` and
`figures/fig9_care_notification.png` are the interface screenshots of the
mobile decision-support prototype ("Bloom") reported in Section 4 of the
